# 문장 구조와 줄바꿈의 개인 선호 pilot

작성일: 2026-10-28. [두 논문 적용 제안](two-paper-application.md)의 첫 검증 단계다. 사용자의 “응 좋은데? 다음 검증해보자”에 따라 진행했다. 별도 model generation 호출 없이 assistant가 가상 사례와 controlled rewrite를 작성했다. 사람의 rewrite나 실제 제품 동작으로 취급하지 않는다.

## 자료와 범위

- [Source·facts·질문·정답](structure-layout-source.json)을 먼저 작성하고 SHA-256을 고정했다: `23c72411ba85f21493f4db0bb359bd0c2875964387928143765c90c33718e9d1`.
- 이후 [rewrite·layout·표시 순서](structure-layout-pilot.json)를 작성하고 사용자에게 제시하기 전에 고정했다: `4adab206db0960157bd06db9b7b27145c64cd196696521013073bbab2beed130`.
- 명사 표현 2개, 삽입 설명 2개, 이미 명확한 문장 2개다. 마지막 두 사례는 rewrite를 source와 동일하게 유지했다. 이는 무변경 목표를 표현하며, 지침이 실제 generation에서도 불필요한 rewrite를 피한다는 증거는 아니다.
- Syntax 비교는 두 version 모두 한 문단이다. Layout 비교는 각 rewrite의 문구·문장 순서를 그대로 두고 문장 사이에 빈 줄만 추가했다. 표시 순서의 첫 항목은 X, 두 번째는 Y이며, 과거 core 비교의 B와 무관하다.

처음 제안한 “정보 순서 유지”는 삽입 설명을 나누는 과정에서 완전히 지키지 못했다. E1은 분모·제외 대상을 먼저 설명하고, E2는 timeout의 의미를 먼저 설명한다. 이 차이를 숨기지 않고 **rewrite 전체에 대한 선호**로 평가한다. Layout 비교만 문구와 순서가 정확히 같다.

## 확인한 내용

| 사례 | 의미 검토 | Source → rewrite 문자 수 |
|---|---|---:|
| N1 | worker, `> 7일` AND `pinned == false`, 필요 조건의 방향, 복원 미검증 유지 | 108 → 91 |
| N2 | controller·operator 역할, 사전 승인, batch당 최대 2회, 자동 승인 없음 유지 | 95 → 86 |
| E1 | 전체 80, timeout 12 제외, 나머지 68의 median error 0.8 m, timeout session 미계산 유지 | 135 → 150 |
| E2 | timeout만으로 실패를 뜻하지 않음, 같은 `request_id` 재시도, 다른 ID의 중복 방지 미검증 유지 | 122 → 132 |
| C1 | `>= 3`, 재실행 금지, unit test 9개, 실제 traffic 미검증 유지 | 98 → 98 |
| C2 | 같은 replay, 48 ms → 36 ms, 원인 미확인, holdout은 제안, 일정 미정 유지 | 102 → 102 |

문자 수는 Python `len`으로 공백·문장부호·backtick을 포함해 센 값이며 token usage가 아니다. Script의 assert로 6개 사례의 필수 literal 존재, layout의 whitespace 제외 동일성, 두 control의 완전 동일성을 확인했다. Literal 일치만으로 의미를 판정하지 않았다.

작성자의 문장별 검토 외에 `/root/reinhart_application` agent가 source facts와 rewrite를 독립적으로 대조했다. 명확한 의미 손실·추가를 찾지 못했다고 보고했다. 이는 agent audit이며 human comprehension 결과와 별개다. 의미 변화가 나중에 발견되면 해당 사례를 실패로 기록하고 조용히 제외하거나 frozen 자료를 덮어쓰지 않는다.

## 사용자에게 제시한 질문

응답 부담을 줄이기 위해 처음에는 세 가지 질문만 제시했다. 나머지 사례는 준비된 자료이며 사용자 검증을 마친 자료로 세지 않는다.

| 순서 | 자료 | 묻는 내용 | 상태 |
|---|---|---|---|
| 1 | E1 rewrite만 공개 | 0.8 m가 어느 session들의 결과인지 자유 응답 | 응답 대기 |
| 2 | N1, X=rewrite / Y=source | 읽기 편한 표현 X / Y / 차이 없음 | 응답 대기 |
| 3 | N2, X=문장 사이 빈 줄 / Y=한 문단 | 읽기 편한 배치 X / Y / 차이 없음 | 응답 대기 |

1번은 본문이 보이는 open-book 범위 확인이다. E1 source·정답·다른 version은 사용자 질문에 포함하지 않았다. 2·3번은 서로 다른 사례이며 E1의 답을 보여 주지 않는다. E1을 이후에 다시 평가한다면 선행 exposure를 기록한다. UI는 preference 질문의 첫 선택지를 기본 선택하므로 명시적으로 제출된 응답만 기록한다. 답을 받지 못한 상태는 동률·승인·정답으로 처리하지 않는다.

## 해석 한계와 다음 판단

- User 1명, 이해 확인 1문항, 표현·배치 각각 1쌍이다. 개인 선호를 구체화하는 용도이며 일반적 효과나 통계적 우위를 주장하지 않는다.
- E1은 한 version만 보았으므로 정답을 맞혀도 source 대비 이해도 향상이나 recall 개선을 뜻하지 않는다. 각 질문은 모든 조건·부정·미검증 상태를 시험하지 않는다.
- Rewrite에서는 어휘·문장 길이·문장 수·어순도 바뀐다. Nominalization 감소 또는 삽입 설명 분리 하나의 효과로 해석하지 않는다. 이번 source는 해당 문제를 일부러 포함한 가상 사례이므로 실제 답변의 문제 빈도를 대표하지 않는다.
- 전체 syntax 자료에서도 N1/N2는 rewrite가 먼저, E1/E2는 source가 먼저여서 category와 표시 위치가 겹친다. 처음 제시한 두 preference 질문에서는 목표 변화가 모두 X다. 이 pilot으로 위치 효과를 배제할 수 없다.
- 사용자에게 평가 목적과 논문 가설이 알려져 있다. 조건 이름을 가렸다는 이유만으로 독립적인 blind 평가라고 부르지 않는다. UI의 실제 줄바꿈 rendering과 읽기 시간은 계측하지 않았다.

응답을 받은 뒤 원문 그대로 기록하고 표현·배치 선호를 구분한다. 기존 B의 선호 이유를 소급해 단정하지 않는다. 선택한 변화가 기존 초안 C와 부합하는지 확인한 다음, 필요하면 별도 B/C generation pilot을 진행한다. 이 단계의 사례를 본 사용자의 이후 평가는 선행 exposure가 있는 평가로 취급한다.

현재 별도 model generation, B/C 비교, provider token usage·latency 측정, active core·manifest·global 설정 변경은 수행하지 않았다. 기존 benchmark 원본도 보존했다.

## 2026-10-28 사용자 응답과 해석 갱신

위 표의 `응답 대기`는 최초 제시 시점의 상태다. 이후 응답은 [별도 기록](structure-layout-responses.json)에 원문 그대로 보존했다. Frozen source·variant·표시 순서는 변경하지 않았다.

| 문항 | 사용자 응답 | 이번 응답에서 확인한 내용 |
|---|---|---|
| N1 표현 비교 | Y 선호. 읽기 편함보다 formal/casual 차이로 보인다고 지적 | 사용자가 이 쌍에서 formal하다고 본 source를 선호했다. Syntax와 register를 함께 바꾼 비교이므로 readability 승패로 세지 않는다 |
| N2 배치 비교 | X 선호 | 동일 문구에서 문장 사이에 빈 줄을 둔 배치를 선호했다. 선택 이유는 별도로 밝히지 않았다 |
| E1 범위 확인 | 미응답 | 정답·오답·이해도 점수를 기록하지 않는다 |

이번 응답은 nominalization 감소가 사용자 선호를 개선한다는 가정을 지지하지 않는다. 반대로 모든 명사형이 더 좋다는 근거도 아니다. Formal한 문체는 이후 후보의 유지 조건으로 삼고, 구조를 바꾸는 경우에도 register가 함께 달라지는지 별도로 확인한다. 이는 이 사용자의 후속 비교를 위한 판단이며 논문의 결론을 반박하는 결과가 아니다.

현재 다음 후보는 **N1의 formal한 원문을 그대로 두고 문장 사이에 빈 줄만 추가한 형태**다. 아래는 두 선호를 반영해 구성한 예시이며, 사용자가 이 조합 자체를 평가한 것은 아니다.

> worker의 snapshot 삭제 수행은 보관 기간 7일 초과와 `pinned == false` 조건이 모두 충족될 때에만 이루어진다.
>
> 삭제한 snapshot의 복원 가능성은 검증하지 않았다.

이 예시는 N1 source와 whitespace 외 동일하다. 이미 본 사례이므로 새 이해도 평가에 쓰지 않는다. 다음 layout 비교에서는 formal한 문구·정보 순서를 고정하고 배치만 바꾸는 방식으로 범위를 좁힌다. 단일 사례의 선호를 모든 문장마다 빈 줄을 넣는 지침으로 확대하지 않는다.

기존 C는 명사 관계와 삽입 설명의 rewrite를 제안하지만 layout을 직접 지시하지 않는다. 따라서 이번 선호를 C의 채택 근거로 쓰지 않고, B/C 24회 generation은 아직 실행하지 않는다. C의 실제 output이 반드시 casual해진다고 단정한 것도 아니다. 기존 B 선호의 원인이 이번 layout 선호와 같았다는 해석 역시 유보한다.

## 2026-10-28 조합에 대한 응답과 후속 layout 비교

위의 N1 source와 문단 분리 조합을 제시한 뒤 사용자는 “응 좋다.”라고 답했다. [응답 기록](structure-layout-responses.json)에 제시 문구와 함께 추가했다. 앞 절의 “사용자가 이 조합 자체를 평가한 것은 아니다”는 이 응답을 받기 전의 상태다. 현재는 해당 예시와 방향에 대한 긍정 응답까지 확보했다. 다른 배치와의 강제 선택이나 comprehension 결과로 해석하지 않는다. E1의 이해 확인 문항은 여전히 미응답이다.

더 긴 답변에서도 문장마다 문단을 나누는지 확인하기 위해 기존 benchmark의 candidate/B API 답변(order 18)에서 whitespace만 바꾼 [후속 비교 자료](layout-followup.json)를 작성했다. 새 generation 호출은 수행하지 않았다.

| 표시 | 배치 | 고정한 요소 |
|---|---|---|
| X | 동작·재시도 두 문장 / 보장 범위·검증 두 문장, 총 두 문단 | 원문 문구·어휘·정보 순서·네 문장 |
| Y | 문장마다 빈 줄, 총 네 문단 | X와 동일 |

후속 자료 SHA-256은 `78f82696c414db09028086960991f23f03c8ccab56ddb5b3a50e11a22f453581`이다. 질문 제시 전에 두 variant가 원문과 whitespace 외 동일함을 assert로 확인했다. X/Y/차이 없음으로 질문했고 현재 응답 대기다. 표시 순서는 고정이며 blind·무작위 비교가 아니다. 원래 B 답변은 단일 줄바꿈과 빈 줄을 함께 썼으므로 X/Y 어느 쪽도 원래 layout과 완전히 동일하지 않다.

이 비교는 user 1명의 배치 선호를 구체화한다. Formal한 표현에 대한 선호를 다른 표현으로 다시 시험하거나, 새 이해도 검증으로 세지 않는다. 일반적 가독성 효과, 읽기 시간, 이후 generation에서 지침 준수 여부는 아직 확인하지 않았다.

## 2026-10-28 후속 Y 선호

사용자는 후속 API 답변 비교에 “Y가 더 좋아”라고 응답했다. [응답 기록](structure-layout-responses.json)에 추가했으며, frozen 후속 자료의 `response: null`은 최초 질문 제시 시점의 상태로 보존했다.

Y는 동일한 네 문장을 각각 별도 문단으로 표시한 version이다. 앞선 N2의 세 문장 사례에서도 같은 방향을 선택했다. 이 두 사례와 N1 조합에 대한 긍정 응답을 바탕으로, 짧은 기술 설명의 다음 검증 지침을 “Formal한 문체와 technical term을 유지한다. 짧은 기술 설명은 문장마다 빈 줄로 구분한다.”로 구체화했다. 선택 이유는 추가로 밝히지 않았으며, 장문·다른 장르까지 일반화하지 않는다.

추가 선호 질문은 마쳤다. 다음으로 같은 사실을 실제 generation에서도 보존하는지와 문단 분리 지시를 따르는지 확인하려고 12회 pilot을 준비했다. 실행 결과와 한계는 [generation 검증 기록](layout-generation-pilot.md)에 분리했다. E1의 comprehension 문항은 계속 미응답이며 점수를 부여하지 않았다.
